## 1. Problem

Burn-in testing measures how key electrical parameters — **Leakage current, Resistance,
Threshold voltage (Vth)** — move over time under stress. The industry-standard check is a
single **PASS/FAIL threshold** at the final checkpoint.

The blind spot: a component can stay *inside* spec at every checkpoint while drifting faster
than its peers, showing an unusual multi-parameter pattern, or heading toward a limit it
hasn't crossed yet. These **latent defects** matter most for high-reliability and space-grade
parts, where field failures are expensive or impossible to service.

## 2. Solution

```
Burn-in CSV → validation → database → anomaly screening → drift forecast
            → risk fusion → explanation → dashboard / engineering report
```

The output is a risk score, a tier (**Space-Safe / Borderline / High-Risk**), and plain-language
reasons — for a human to review. The system never auto-rejects a component on its own.

**Distribution on the bundled dataset** (9,562 components): PASS 3,763 · HOLD 4,001 ·
REJECT 1,765 · MONITOR 33.

## 3. Key Features

- **CSV burn-in ingestion** — `POST /api/burnin/upload`, validates filetype (.csv only),
  size (10 MB max), empty and malformed files
- **Data validation & preprocessing** — column, ID, range and timestamp checks before
  anything is stored or scored (`database/validation.py`, `database/preprocessing.py`)
- **Anomaly screening** (Module A) — lot-relative z-scores + per-part-type Isolation Forest
- **168h drift forecasting** (Module B) — Random Forest + Gradient Boosting fused by a Ridge
  meta-learner, with quantile intervals
- **Fused risk scoring** (Module C) — weighted anomaly + drift + uncertainty score with hard
  floors for spec failures (see [§4](#4-ai--ml-architecture))
- **Explainability** — every component report ships human-readable reasons; optional SHAP
  attribution per flagged component
- **Human disposition workflow** — PASS / HOLD / QUARANTINE with comments, append-only
  history per component
- **JWT auth + roles** — `admin` / `engineer` / `reviewer`; reviewer is read-only,
  uploads and dispositions require admin/engineer
- **Audit trail** — append-only log of logins, permission failures and dispositions
- **Single-service deploy** — FastAPI serves the API and the static dashboard from one URL

## 4. AI / ML Architecture

Fitted artifact-based pipeline (`backend/database/ml_inference.py`), trained in
[`notebooks/`](notebooks/) on a 10,000-row synthetic burn-in dataset — 20 lots, part types
MOSFET / Op-Amp IC / Voltage Regulator IC / Digital Logic IC, stress types Thermal-High /
Radiation-Low / Cycling-Medium (generated by
[`scripts/generate_burn_in_dataset.py`](scripts/generate_burn_in_dataset.py)).

| Module | What it does |
|---|---|
| **A — Anomaly** (`anomaly_detection.ipynb`) | Lot-relative MAD z-scores, one Isolation Forest per part type (global fallback under 30 rows), early-drift severity; absolute spec failures are floored to a minimum risk score. Falls back to a pure statistical scorer if the artifact can't load. |
| **B — Drift** (`drift_prediction.ipynb`) | Forecasts Leakage, Resistance, Vth to 168h. Tuned RF + multi-output Gradient Boosting fused by Ridge, quantile regressors (α = 0.05/0.95). Uncertainty = 0.6 × interval width + 0.4 × model disagreement. Safety-slope flag when predicted drift rate exceeds the 99th percentile of Safe training parts. |
| **C — Risk** (`reliability_index.ipynb`) | Fuses the modules into one score (weights from `backend/models/config.json`): |

```
Risk = 0.278 × Anomaly + 0.670 × Predicted Drift + 0.052 × Uncertainty
```

Floored to ≥ 65 on absolute spec failure or safety-slope trip, clipped to [0, 100].

| Tier | Score | `risk_level` |
|---|---|---|
| Space-Safe | < 21.8 | LOW |
| Borderline | 21.8 – 65.0 | MEDIUM |
| High-Risk | ≥ 65.0 | HIGH |

Weights found by a 500-draw Dirichlet search targeting ≥ 98% recall on validation "Fail"
cases — achieved: 98.1% val recall, 90.9% val AUC, 97.4% test recall at Borderline+.

## 5. Human Review

Every AI decision is shown with its risk score, confidence, tier and full telemetry. The ML
decision stays an immutable audit record; on top of it an engineer records a formal
disposition:

- **PASS** — cleared for the batch
- **HOLD** — re-test / bake
- **QUARANTINE** — isolate or reject

…with an optional justification comment, kept as an **append-only history**
(`GET /api/components/{id}/reviews`). Until a human acts, the component is "not yet reviewed".
`reviewer` accounts cannot submit dispositions (403).

## 6. Security

Implemented in `backend/app/core/security.py` and `backend/app/api/auth.py`:

- **JWT auth** (HS256, PyJWT) — access tokens default to **8 hours**
  (`SAGE_ACCESS_TOKEN_EXPIRE_MINUTES`), signed with `SAGE_JWT_SECRET` read from the
  environment; the app refuses to start without it (no hardcoded fallback secret)
- **Role-based access control** — `admin` / `engineer` / `reviewer` enforced per endpoint via
  `require_roles()`; users live in the database (seeded on first run)
- **bcrypt password hashing** with random salts and constant-time verification
- **Login rate limiting** — 5 failed attempts per IP per 5 minutes → `429` with `Retry-After`,
  cleared on successful login
- **Audit trail** — append-only records for logins, permission failures and review actions
  (`GET /api/system/audit-logs`, admin only)
- **CORS allow-list** — origins from `ALLOWED_ORIGINS` env var, credentials off
- **No secrets in source** — `.env` is git-ignored; `.env.example` is the template

## 10. Local Setup

**Requirements**: Python 3.13

```bash
cd backend
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env              # then set SAGE_JWT_SECRET, e.g.:
# python -c "import secrets; print(secrets.token_urlsafe(48))"

python -m database init                                   # create tables
python -m database ingest data/burn_in_dataset.csv        # load demo data (optional)

uvicorn app.main:app --reload
```

- Dashboard: <http://127.0.0.1:8000/app>
- API docs: <http://127.0.0.1:8000/docs>
- Health: <http://127.0.0.1:8000/health>

Demo accounts are seeded automatically on first run: **admin**, **engineer**, **reviewer**
(password: `sage2026`). Change them before any real deployment.

**Docker:**

```bash
SAGE_JWT_SECRET=$(python -c "import secrets; print(secrets.token_urlsafe(48))") \
docker compose up --build
```

```bash

```

**188 tests** across 18 files — API contracts, auth/RBAC, rate limiting, audit, reviews,
database CRUD, validation, preprocessing, ingestion, and ML inference.

> Note: tests that read real data need the bundled dataset ingested first
> (`python -m database ingest data/burn_in_dataset.csv`). API tests run against an in-memory
> database — no PostgreSQL required.

## 12. Limitations

- **Synthetic dataset** — the bundled 10,000-row dataset is generated, not from real component
  testing; metrics in §4 are validation/test numbers on this data, not real-world accuracy.
- **Explainability is opt-in** — SHAP is off by default (~1.3 s/row); enable per run with
  `python -m database ingest <csv> --explain N`.
- **Free-tier deploy** — Render free plan has no persistent disk (redeploys reset SQLite) and
  sleeps after inactivity (~50s cold start).
- **Single-process rate limiting** — login lockout state is in-process memory.
